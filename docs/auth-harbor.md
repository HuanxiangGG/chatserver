# 泊岸认证页面：夜航与清晨

登录与注册共用 `frontend/src/harbor-scene.tsx` 的原创 SVG 几何：同一座灯塔、防波堤、远岸和港灯。登录采用墨蓝夜色、灯束和分段水面倒影；注册保留相同构图，以晨光、小船和航迹区分。没有复制第三方素材，没有下载图片，也不依赖图片加载后才显示表单。场景只承担装饰职责，`aria-hidden` 不干扰表单阅读顺序。

桌面场景延伸至表单附近，表单文字保持独立对比度。手机使用单独的横向取景窗口，保留灯塔与出港小船；不把桌面双栏缩小。手机注册表单可以在 `.auth-screen` 内自然滚动。输入框字体至少 16px，页面保留浏览器双指缩放。

`visualViewport` 的高度与偏移由现有共享视口模块处理。检测到软键盘后，认证页隐藏场景和重复品牌区域；提交按钮仍可通过独立滚动到达。键盘收起后场景恢复。水面与灯束的轻微动画在字段聚焦、用户开始输入或系统设置减少动态效果时停止。

现有登录、注册、找回密码和重置密码 API、Cookie 和安全检查保留。密码错误不清空用户名、邮箱或密码，登录凭证错误显示在密码字段附近，字段校验有对应的可访问说明。提交锁阻止重复请求。登录前可切换简体中文和 English，翻译走现有词典检查。

## 可重复的隔离浏览器验证

```bash
# 使用已有测试环境配置，DATABASE_URL 的库名必须以 _test 结尾。
# UI_TEST_BASE_URL 只允许 localhost/127.0.0.1 的 HTTP 测试站点。
UI_TEST_BASE_URL=http://localhost:5173 node scripts/test-auth-harbor.mjs
```

脚本需要已运行的本地 API/Vite 服务和已安装的 Playwright Chromium/WebKit。它会在测试库中真实注册两个唯一账号并登录；正常注册限流保持开启。请使用独立的测试 Redis 数据库或在全套验收中为注册账号数量预留配额，不要连接生产服务。截图默认保存在忽略 Git 的 `test-results/browser/auth-harbor/`，可使用 `AUTH_HARBOR_OUTPUT` 指定 `file:` 输出目录。

实际完成的检查：

- Chromium 和 WebKit 各检查桌面 1440×1000 与手机 390×844 的登录、注册页面。
- 中英文标题即时切换，页面无横向溢出，场景和输入区可见。
- 每个浏览器真实注册一个账号、验证重复提交只发出一次请求，再通过错误密码和正确密码依次登录。
- 错误密码保留已填写字段，错误位置靠近密码字段。
- 手机模拟键盘打开后场景隐藏，390px 高的可视区域内可滚到提交按钮；关闭后场景与完整布局恢复。
- 没有捕获到未处理的页面异常。

本轮浏览器验收通过。`npm run i18n:check` 和前端类型检查通过。根目录的完整构建和测试由社区功能交付一并执行。

交付截图位于工作区 `outputs/community-review/`，包含两种引擎的桌面登录、桌面注册、手机登录、手机注册、键盘模拟和恢复截图。`*-mobile-register-keyboard-simulated.png` 只截取键盘上方 390×390 的模拟可视区域，没有绘制假的系统键盘。

**设备边界：** Chromium/WebKit 自动化和 `visualViewport` 模拟不等于 iPhone Safari 或 Android Chrome 实体手机。当前没有连接实体设备；真机软键盘、输入法和地址栏仍需后续目标设备验收。本次未向生产库写测试数据，也没有更改数据库或部署架构。
