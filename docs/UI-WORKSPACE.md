# 聊天、社区和工单工作区改版

本轮沿用现有账号、会话、附件权限和 Socket.IO 事件。登录与注册保留夜航／清晨港景；应用内部使用靛蓝强调色、相邻分区和紧凑列表。没有新增数据库迁移或环境变量，没有改变 Docker Compose + Caddy、数据库和上传卷。

## 界面与实际问题

| 原问题 | 修改 |
| --- | --- |
| 桌面导航与会话栏占宽较多，社区重复显示账号 | 默认紧凑导航为 64px，保留展开选择；唯一账号菜单汇集资料、设置、主题与退出 |
| 每条手机消息长期显示操作按钮，菜单重复撤回入口 | 平时收起；点按消息、键盘聚焦或悬停显示操作，统一消息菜单与复制反馈 |
| 设置页同时展开很多长表单，社区设置前面重复整个首页 | 个人与社区设置按真实栏目切换；手机使用可展开的栏目导航 |
| 好友页面每人占一大张卡片 | 改为按行浏览的列表，保留聊天、资料与删除确认 |
| 工单列表缺少真实摘要、更新时间与等待方向 | 读取当前访问者可见的最后消息，显示等待处理人员／用户回复、处理人、时间与未读文字 |
| 工单聊天头部操作占高，加载后的刷新失败不明显 | 详情操作收进菜单；保留可复制编号、关闭状态和可重试的错误 |
| 机器人安装、配置和移除混在同一区域 | 分为可安装与已安装；授权频道、保存状态、错误、卸载确认各有位置 |
| 表单未保存就离开，或保存途中继续修改导致状态误标成功 | 统一未保存状态；链接、栏目、浏览器返回／前进和刷新均有提醒；保存时冻结当前表单字段 |

工单摘要不扩展阅读权限：认领前仍只返回编号、类别和等待时间等原有脱敏字段。被本地隐藏的消息不会重新出现在摘要里；撤回消息不暴露正文或附件文件名。等待状态来自最后一条未撤回消息，关闭后的工单不再显示等待回复。

## 修复的聊天状态问题

- 草稿曾属于 ChatPage 组件，离开整个页面就被清理。现在按当前账号保存在浏览器内存中，切换页面或会话可以继续编辑；退出／切换账号会清理，不写入日志或本地持久存储。
- 原发送队列在页面卸载后只完成当前请求，清掉余下消息。现在队列与原始幂等编号一起保留，普通导航不终止发送；失败附件沿用上传结果和消息编号重试。退出账号停止后续投递并释放预览资源。
- 阅读位置原先没有跨页面保存；实现时也发现消息编号在分组外层，必须用同一真实消息锚点定位。现在返回时重新向服务器验证权限并读取锚点上下文；返回最新消息会真正加载最新一页。
- WebKit 的默认 Tab 顺序可能跳过按钮，使焦点离开消息菜单进入背景输入框。共享弹窗现在显式管理每一步 Tab／Shift+Tab。关闭时返回触发按钮，但「回复」已经把焦点交给输入框时不会抢回。

这些内存草稿不承诺刷新、关闭标签页或设备重启后恢复。消息是否送达仍由真实 API／Socket 回执决定；失败快照不会伪装成成功消息。

## 本地验收

使用独立的 `_test` PostgreSQL 数据库和本机 Redis，所有新增账号、图片、社区与工单均为隔离测试数据。浏览器脚本拒绝公网目标，恢复码与 Cookie 不写入截图目录。

```bash
npm run i18n:check
npm run typecheck
npm run build
npm run test
BROWSER_TEST_SCRIPT=scripts/test-ui-workspace.mjs npm run test:browser:ci
BROWSER_TEST_SCRIPT=scripts/test-settings-workspace.mjs npm run test:browser:ci
```

浏览器包装器需要测试数据库和 Redis 已启动，且 `DATABASE_URL` 指向以 `_test` 结尾的库；沿用 README 的测试环境变量设置。每个验收任务使用独立 Redis 数据库隔离注册配额，不关闭生产限流。

`test-ui-workspace.mjs` 检查 Chromium／WebKit、360／390／768／1440px、中英与浅深主题，覆盖登录、注册、聊天、好友、群聊、社区、频道、成员、工单、游客、机器人与设置；实际发送短消息、长消息和图片，注入一次请求失败后重试，检查 IME、焦点、历史阅读、草稿、工单筛选及管理员／游客同一段历史。

`test-settings-workspace.mjs` 检查两种引擎的桌面和手机，真实保存设置、取消／放弃修改、返回／刷新提醒、机器人安装／配置／移除与成员危险操作确认。旧有认证、社区、游客、机器人和管理员工单套件继续执行。

手机软键盘通过 `visualViewport` 缩小与还原模拟；中文输入法通过组合输入事件检查。没有实体 iPhone 或 Android，本轮不能据此声称真机 Safari／Chrome、真实中文选词或地址栏全部通过。截图中的消息与用户名称是测试数据，不会出现在生产库。

## 更新与数据核对

在服务器原仓库目录执行，保留原 `COMPOSE_FILE`、Compose 项目名、`.env` 和卷名：

```bash
git status --short
umask 077
audit_dir="$HOME/harbor-update-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$audit_dir"
./scripts/backup.sh
./scripts/data-inventory.sh > "$audit_dir/before.txt"
git pull --ff-only
docker compose up -d --build
docker compose exec -T backend npx prisma migrate deploy
docker compose ps
./scripts/data-inventory.sh > "$audit_dir/after.txt"
diff -u "$audit_dir/before.txt" "$audit_dir/after.txt"
```

本轮需重建前后端镜像，`migrate deploy` 仅按既有机制应用尚未执行的增量迁移，本轮本身没有新迁移。更新后检查原用户登录、已有工单／聊天历史和旧附件下载；核对清单中原数据行数与上传文件，正常使用期间新增记录可以使数量增加。不要更改卷名，不使用删除卷、重置数据库或覆盖上传目录的命令。

生产部署未由本次开发自动执行。没有启用新的公开入口，也没有修改 Caddy 的 HTTPS 配置。
